PART 1: PRODUCT REQUIREMENTS DOCUMENT (PRD)

1.1 Product Overview

Proto-Prometheus is a decentralized AI mining network where users contribute GPU compute, AI prompts, or data to collectively power an open-source large language model. The model generates novel, verifiable insights. These insights become licensable Knowledge Assets. The network monetizes through API fees, Eureka Bonds (bounties), and insight licensing. All protocol revenue buys back and burns the PROTO token.

1.2 Core User Personas

Persona Goal Device
Compute Miner Earn tokens by contributing idle GPU cycles Gaming PC, workstation
Prompt Explorer Earn tokens by generating prompts that yield valuable insights Any computer
Data Provider Earn royalties by uploading novel datasets Phone, IoT, PC
Verifier/Curator Earn by staking on insight validity and value Any device
API Customer Pay to use the decentralized AI inference Server, app
Eureka Bond Creator Deposit bounties for specific discoveries Institutional wallet

1.3 Functional Requirements

FR1: Compute Mining

· User downloads desktop app and clicks "Start Mining"
· App joins Petals swarm, downloads a model shard
· GPU runs inference/training on the shard
· Proof-of-compute is reported via heartbeat
· Smart contract mints PROTO rewards proportionally

FR2: Prompt Exploration

· User enables "Auto-Explore" mode
· Local small explorer AI generates prompts
· Prompts routed to Petals swarm for response generation
· Response submitted as insight with stake
· Verified insights earn block rewards + future royalties

FR3: Data Provision

· User uploads data file via app
· File pinned to IPFS, registered on OriginTrail DKG
· Data provenance tracked
· If data contributes to a licensed insight, provider earns 20% royalty

FR4: Insight Verification

· Submitted insight enters verification window
· Verifiers stake PROTO on validity
· Oracle (trusted initially, TEE-based later) confirms novelty
· Verified insights become Knowledge Assets on DKG

FR5: Knowledge Marketplace

· Verified insights listed as licensable assets
· Buyers purchase licenses with stablecoins
· Smart contract auto-splits royalties: 40% prompt miner, 35% compute miners, 20% data providers, 5% protocol

FR6: Eureka Bonds

· Creator deposits stablecoins, defines discovery criteria, sets deadline
· Miners target the bond's objective
· First verified insight matching criteria triggers auto-payout
· Protocol takes 2% creation fee + 5% success fee

FR7: Prediction Markets

· When insight is submitted, prediction market opens
· Users stake PROTO on YES (will be verified & licensed) or NO
· Winning side splits losing stakes
· Protocol takes 3% fee

FR8: Decentralized Inference API

· OpenAI-compatible API endpoint
· Paying customers query the Petals swarm
· 20% protocol fee, 80% to compute miners
· Fees in USDC, used to buy and burn PROTO

FR9: Token Burn Engine

· Aggregates fees from all revenue streams
· Periodically swaps stablecoins for PROTO on DEX
· Burns purchased PROTO

FR10: Wallet Abstraction

· Users sign in with Google/email
· Non-custodial wallet auto-created via Web3Auth
· Gas sponsored by protocol initially

1.4 Non-Functional Requirements

· Security: Smart contracts audited. TEE for oracle in Phase 2.
· Scalability: Petals swarm scales horizontally with miners.
· Latency: Inference responses <5 seconds for API customers.
· Availability: 99.9% swarm uptime via redundancy.
· UX: One-click mining. No crypto jargon in UI.

```solidity
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/AccessControl.sol";

contract ProtoToken is ERC20, AccessControl {
bytes32 public constant MINTER_ROLE = keccak256("MINTER_ROLE");
bytes32 public constant BURNER_ROLE = keccak256("BURNER_ROLE");

uint256 public constant MAX_SUPPLY = 1_000_000_000 * 10**18;
uint256 public totalMinted;

event TokensBurned(uint256 amount, address burner);

constructor() ERC20("ProtoToken", "PROTO") {
_grantRole(DEFAULT_ADMIN_ROLE, msg.sender);
_grantRole(MINTER_ROLE, msg.sender);
_grantRole(BURNER_ROLE, msg.sender);
}

function mint(address to, uint256 amount) external onlyRole(MINTER_ROLE) {
require(totalMinted + amount <= MAX_SUPPLY, "Exceeds max supply");
totalMinted += amount;
_mint(to, amount);
}

function burn(uint256 amount) external onlyRole(BURNER_ROLE) {
_burn(msg.sender, amount);
emit TokensBurned(amount, msg.sender);
}

function burnFrom(address from, uint256 amount) external onlyRole(BURNER_ROLE) {
_spendAllowance(from, msg.sender, amount);
_burn(from, amount);
emit TokensBurned(amount, from);
}
}
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/access/Ownable.sol";
import "./ProtoToken.sol";

contract MiningPool is Ownable {
ProtoToken public token;

uint256 public rewardPerSecond = 1 ether; // 1 PROTO per second (adjustable)
uint256 public constant MAX_REWARD_PER_SECOND = 10 ether;

mapping(address => uint256) public lastCheckIn;
mapping(address => uint256) public pendingRewards;
mapping(address => uint256) public totalEarned;

event CheckIn(address indexed miner, uint256 timestamp);
event RewardsClaimed(address indexed miner, uint256 amount);

constructor(address _token) Ownable(msg.sender) {
token = ProtoToken(_token);
}

function checkIn() external {
if (lastCheckIn[msg.sender] != 0) {
uint256 elapsed = block.timestamp - lastCheckIn[msg.sender];
pendingRewards[msg.sender] += elapsed * rewardPerSecond;
}
lastCheckIn[msg.sender] = block.timestamp;
emit CheckIn(msg.sender, block.timestamp);
}

function claimRewards() external {
uint256 reward = pendingRewards[msg.sender];
require(reward > 0, "No rewards to claim");
pendingRewards[msg.sender] = 0;
totalEarned[msg.sender] += reward;
token.mint(msg.sender, reward);
emit RewardsClaimed(msg.sender, reward);
}

function getPendingRewards(address miner) external view returns (uint256) {
uint256 pending = pendingRewards[miner];
if (lastCheckIn[miner] != 0) {
pending += (block.timestamp - lastCheckIn[miner]) * rewardPerSecond;
}
return pending;
}

function setRewardPerSecond(uint256 _reward) external onlyOwner {
require(_reward <= MAX_REWARD_PER_SECOND, "Too high");
rewardPerSecond = _reward;
}
}
```

InsightVerification.sol

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/access/AccessControl.sol";
import "./ProtoToken.sol";

contract InsightVerification is AccessControl {
bytes32 public constant VERIFIER_ROLE = keccak256("VERIFIER_ROLE");

ProtoToken public token;

uint256 public constant REWARD = 100 ether; // 100 PROTO per verified insight
uint256 public constant STAKE_AMOUNT = 10 ether;

enum Status { Pending, Verified, Rejected, Licensed }

struct Insight {
bytes32 promptHash;
bytes32 responseHash;
address submitter;
Status status;
uint256 stake;
uint256 timestamp;
string metadataURI; // IPFS link to full prompt/response
}

Insight[] public insights;
mapping(uint256 => address[]) public dataContributors; // insightId → contributors

event InsightSubmitted(uint256 indexed id, address indexed submitter, bytes32 promptHash);
event InsightVerified(uint256 indexed id, Status status);
event InsightLicensed(uint256 indexed id, uint256 amount, address licensee);

constructor(address _token) {
token = ProtoToken(_token);
_grantRole(DEFAULT_ADMIN_ROLE, msg.sender);
_grantRole(VERIFIER_ROLE, msg.sender);
}

function submitInsight(
bytes32 promptHash,
bytes32 responseHash,
string calldata metadataURI,
address[] calldata contributors
) external {
require(token.transferFrom(msg.sender, address(this), STAKE_AMOUNT), "Stake failed");

uint256 id = insights.length;
insights.push(Insight({
promptHash: promptHash,
responseHash: responseHash,
submitter: msg.sender,
status: Status.Pending,
stake: STAKE_AMOUNT,
timestamp: block.timestamp,
metadataURI: metadataURI
}));

if (contributors.length > 0) {
dataContributors[id] = contributors;
}

emit InsightSubmitted(id, msg.sender, promptHash);
}

function verifyInsight(uint256 id, bool approved) external onlyRole(VERIFIER_ROLE) {
Insight storage ins = insights[id];
require(ins.status == Status.Pending, "Already resolved");

if (approved) {
ins.status = Status.Verified;
// Mint reward
token.mint(ins.submitter, REWARD);
// Return stake
token.transfer(ins.submitter, ins.stake);
} else {
ins.status = Status.Rejected;
// Stake is forfeited (stays in contract for burning)
}

emit InsightVerified(id, ins.status);
}

function licenseInsight(uint256 id) external payable {
Insight storage ins = insights[id];
require(ins.status == Status.Verified, "Not verified");

uint256 amount = msg.value;
ins.status = Status.Licensed;

// Royalty split: 40% prompt miner, 35% compute pool, 20% data, 5% protocol
uint256 promptShare = (amount * 40) / 100;
uint256 computeShare = (amount * 35) / 100;
uint256 dataShare = (amount * 20) / 100;
// 5% stays in contract as protocol fee

payable(ins.submitter).transfer(promptShare);
// Compute share goes to MiningPool (simplified here)
// Data share distributed to contributors

emit InsightLicensed(id, amount, msg.sender);
}

function getInsightCount() external view returns (uint256) {
return insights.length;
}
}
```

EurekaBond.sol

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/access/Ownable.sol";
import "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract EurekaBond is Ownable {
uint256 public constant CREATION_FEE_BPS = 200; // 2%
uint256 public constant SUCCESS_FEE_BPS = 500; // 5%

struct Bond {
address creator;
IERC20 rewardToken;
uint256 rewardAmount;
string criteria; // IPFS URI with detailed criteria
uint256 deadline;
bool claimed;
address claimer;
uint256 insightId;
}

Bond[] public bonds;

event BondCreated(uint256 indexed id, address creator, uint256 amount, uint256 deadline);
event BondClaimed(uint256 indexed id, address claimer, uint256 insightId);
event BondRefunded(uint256 indexed id);

function createBond(
IERC20 _rewardToken,
uint256 _rewardAmount,
string calldata _criteria,
uint256 _durationDays
) external {
require(_rewardAmount > 0, "Reward must be > 0");
require(_durationDays > 0, "Duration must be > 0");

uint256 fee = (_rewardAmount * CREATION_FEE_BPS) / 10000;
uint256 total = _rewardAmount + fee;

require(_rewardToken.transferFrom(msg.sender, address(this), total), "Transfer failed");

bonds.push(Bond({
creator: msg.sender,
rewardToken: _rewardToken,
rewardAmount: _rewardAmount,
criteria: _criteria,
deadline: block.timestamp + (_durationDays * 1 days),
claimed: false,
claimer: address(0),
insightId: 0
}));

emit BondCreated(bonds.length - 1, msg.sender, _rewardAmount, block.timestamp + (_durationDays * 1 days));
}

function claimBond(uint256 bondId, uint256 insightId, address claimer) external onlyOwner {
Bond storage bond = bonds[bondId];
require(!bond.claimed, "Already claimed");
require(block.timestamp <= bond.deadline, "Deadline passed");

bond.claimed = true;
bond.claimer = claimer;
bond.insightId = insightId;

// Pay reward to claimer
bond.rewardToken.transfer(claimer, bond.rewardAmount);

emit BondClaimed(bondId, claimer, insightId);
}

function refundBond(uint256 bondId) external {
Bond storage bond = bonds[bondId];
require(block.timestamp > bond.deadline, "Deadline not passed");
require(!bond.claimed, "Already claimed");

bond.claimed = true;
bond.rewardToken.transfer(bond.creator, bond.rewardAmount);

emit BondRefunded(bondId);
}

function getBondCount() external view returns (uint256) {
return bonds.length;
}
}
```

· They don’t need a GPU, don’t need to craft prompts, don’t need data.
· If they stake early on a $500,000 insight and have even a small stake relative to the curation pool, that 3% slice might still yield a 10x return on their staked amount.
· It’s essentially venture capital for AI discoveries—high risk, but asymmetric upside.

Real-world analogy: Early-stage angel investors take 1-5% equity. They don’t need 40% because they diversify across many bets and only need one massive hit.

---

2. Validator / Oracle Node (5% of licensing, plus slashing rewards)

Why take 5%? Because it’s a recurring, low-effort fee on every single insight that gets licensed. And they also earn from slashing false ones.

· A Validator runs lightweight software (or a TEE node). Once set up, it’s nearly passive.
· With 1,000 insights verified per month, and even 100 of those licensed at an average $10,000, that’s $50,000 in fees shared among a small pool of validators.
· Additionally, they earn slashed stakes from challenges they win—which can be extremely profitable.

Real-world analogy: Auditors take a small percentage of transactions but earn millions because they process huge volume with a standardized process.

---

3. Data Provider (15-20% of licensing)

Why take 15%? Because the data you upload may generate passive royalties for years across many different insights, with zero additional effort.

· A farmer’s soil dataset might contribute to 20 different agricultural insights. Each one paying 15% of its license fee. That’s a cumulative effect.
· Data is a one-time contribution. If your data helps train a model that becomes the basis for a whole industry, you’ll earn a continuous revenue stream.

Real-world analogy: Songwriters get a small royalty per stream, but with millions of streams, it becomes a fortune.

---

4. Compute Miner (25-35% of licensing + per-task API fees)

Why take 25%? Because you’re already earning inflationary PROTO rewards and direct API payments on top of that royalty.

· Compute miners get paid for every second their GPU is connected, plus they get a cut of every paid inference request.
· The royalty share is just the bonus—the icing on a cake they’re already being paid to bake.
· For a gaming PC sitting idle, even a small slice of a big insight is pure profit on top of electricity cost.

Real-world analogy: A landlord renting out an apartment also gets a share of the property value appreciation. The royalty is the appreciation, the rent is the API/inflation.

---

5. Model Trainer (10% of licensing)

Why take 10%? Because this is the highest-value, highest-skill contribution after the prompt. A well-trained model makes all insights more valuable.

· Trainers contribute to the collective brain’s improvement. They get a direct cut of every insight that uses the model version they helped train.
· 10% of a $1,000,000 insight from a model you fine-tuned is $100,000. If you do this multiple times, it’s massive.
· It’s a career path for ML engineers to earn passive income from their training runs.

Real-world analogy: A professor who publishes a groundbreaking algorithm doesn’t take 100% of all future products using it; they get royalties or citations that accumulate over their career.

---

6. Prompt Explorer (40% of licensing)

Why would they share? They wouldn’t get 40% if the ecosystem didn’t exist. They need compute, they need verification, they need data and curation to prove value. The network enables them to monetize something that otherwise would be a fun experiment.

· 40% of a verified, licensed insight is fair because they took the creative risk and staked their own PROTO.
· The remaining 60% funds the infrastructure that makes their insight liquid—without it, they couldn’t sell it.

---

7. Liquidity Provider (trading fees + potential PROTO incentives)

Why would they add liquidity? Because they earn swap fees on every trade (0.3% typical DEX fee) plus they may get additional PROTO rewards. Their return is based on volume, not insight licensing. If the token becomes heavily traded, a small percentage of millions in volume is huge.

---

The Psychological Hook: “Small Slice of a Growing Pie”

People accept small percentages when:

1. The pie is huge. A 3% curator stake on a $10M drug discovery licensing deal is $300,000.
2. It’s passive. Data, validation, and liquidity require minimal ongoing effort after setup.
3. It’s diversified. Curators don’t bet on one insight; they bet on 100. A few big wins more than cover the losses.
4. There’s no alternative. You can’t get 100% of an AI insight license by yourself—you need the network to verify, host, and sell it. The network’s fee is the cost of doing business.
5. Early participants get tokens. Those tokens could appreciate 10x if the network succeeds, making their effective percentage far higher than it appears initially.

---

Could We Adjust Percentages? Absolutely.

The DAO can vote to tweak splits based on market dynamics. If we see we need more curators, we raise the curator share. The initial numbers are a starting point, not a dogma.

But the fundamental principle is: Every role is designed so that the expected value of their contribution, given their effort/capital/risk, is positive and competitive with alternatives.
