FLOW 01 · Entry Point
User Onboarding
Every new user goes through World ID verification, gets an embedded wallet (no seed phrase), an on-chain ZK-SoulBound Token, and a V-Score starting at seed tier. Referrals give $5 to both sides.
1
App Launch
User opens VIVA. Checks for existing session/wallet.
screens/Auth/Landing.tsx
2
World ID Verify
Proof-of-human via World ID Orb or Device credential. Prevents bots. One account per human.
POST /v1/auth/world-id-verify { nullifier_hash, proof, merkle_root }
3
Embedded Wallet Created
Dynamic.xyz / Privy creates wallet silently. No seed phrase shown to user. Wallet address stored.
Dynamic.createEmbeddedWallet() → wallet_address saved to users table
4
ZK-SBT Issued On-Chain
Non-transferable SoulBound Token minted on Base L2. Tier = SEED. Linked to wallet forever.
ZKSBT.issue(wallet_address) → tier: SEED, tokenId: auto → tx_hash saved
5
V-Score Initialized
V-Score = 0, tier = seed. All 5 rings at 0. GNN model registers new user node.
POST /v1/vscore/init { userId, tier: "seed", score: 0 } rings: {social:0, wealth:0, activity:0, sleep:0, nutrition:0}
6
Referral Check
If user joined via referral link — $5 VIVA credited to both new user and referrer instantly.
VIVAToken.mint(newUser, 5e18, REFERRAL) VIVAToken.mint(referrer, 5e18, REFERRAL) referrals table: { referee_id, referrer_id, reward_claimed: true }
+$5 VIVA both sides
7
AI Twin Onboarding
User sets autonomy level: suggest / semi-auto / full-auto. Twin profile created.
PUT /v1/twin/autonomy { level: "suggest" } twin_profiles INSERT
8
HomeCanvas Shown
5-ring biometric dashboard displays. All rings at 0. User sees their earning potential.
screens/HomeCanvas/index.tsx → useVScoreStore().score = 0 → useVScoreStore().rings = all zeros

FLOW 06 · Creator Economy
YouToken Buy
Every creator has a personal ERC-20 on a bonding curve. Buy → price goes up, creator earns 5% fee instantly. Sell → price drops. Creator exposure is literally tradeable.
1
View Creator Profile
Buyer taps creator. Profile shows current token price, market cap, holder count.
GET /v1/wallet/youtoken/price/{creatorId} → { price: 0.042 VIVA, mktCap: 4200, holders: 100, totalSupply: 100000 }
2
Bonding Curve Price
Price = reserveBalance × 2 / totalSupply. Increases with each buy. Sqrt-based curve.
// YouToken.sol function currentPrice() public view { return reserveBalance * 2 / totalSupply; } // Buy 50 VIVA → receive X tokens // where X = f(reserveBalance, totalSupply)
3
Buyer Taps Buy
Inputs VIVA amount. Preview shows tokens received + new price after purchase.
POST /v1/wallet/youtoken/buy/{creatorId} { vivaAmount: 50 } → preview: { tokensOut: 892, newPrice: 0.046 }
4
On-Chain Buy Executes
$VIVA split: 5% to creator, 2% to treasury, 93% to bonding curve reserve.
YouToken.buy(50e18) // inside contract: fee = 50 * 500 / 10000 // 2.5 VIVA creator trsy = 50 * 200 / 10000 // 1.0 VIVA treasury net = 50 - fee - trsy // 46.5 VIVA to curve tokens = _buyTokensForViva(net) balanceOf[buyer] += tokens totalSupply += tokens reserveBalance += net
5
Creator Earns Fee Instantly
2.5 VIVA hits creator wallet. No delay. Every buy = passive income for creator.
youtoken_holdings UPSERT { holder_id, creator_id, amount } wallet_tx INSERT: creator +2.5 VIVA wallet_tx INSERT: buyer +892 $CREATOR
+2.5 VIVA instant fee to creator
6
Price Increases
New price visible on creator profile. Early holders see unrealized gain. Can sell any time.
currentPrice() = new reserveBalance*2 / new totalSupply // 0.042 → 0.046 VIVA (after 50 VIVA buy)

FLOW 07 · Privacy-First Health
Health ZK
Raw biometric data never leaves the device. ZK-proof (Iden3 / Groth16) proves statements like "slept 7–9 hrs" without revealing the exact value. Server stores only hash + score.
1
HealthKit / Google Fit
Native health data read on-device. Raw values: sleep duration, steps, calories, macros. Never serialized to network.
// health/HealthKitService.ts const sleep = await HealthKit.getSleepSamples() // stays in memory on device only
2
ZK-Proof Generated On-Device
Iden3 Groth16 circuit proves the statement without revealing raw data. Proof = ~256 bytes.
// iden3 circuit (simplified): // Private input: durationMinutes = 454 // Public input: min=420, max=540 // Proves: 420 ≤ 454 ≤ 540 // WITHOUT revealing 454 zkProof = await iden3.prove(circuit, inputs) // proof: { pi_a, pi_b, pi_c, publicSignals }
3
POST With Proof (No Raw Data)
Request contains: date, ZK-proof, aggregate category (e.g. steps "8000–8999"). No exact values.
POST /v1/health/sleep { date: "2026-06-08", durationMinutes: 450, // ← bucketed/rounded quality: 0.82, // ← derived score zkProof: "0x3a7f..." // ← proof bytes }
4
Server Verifies Proof
Health service verifies ZK proof signature using Iden3 verifier. If invalid → 400. If valid → compute score.
# health/src/routers/biometrics.py result = iden3.verify(zkProof, publicSignals) if not result.valid: raise HTTPException(400, "Invalid proof") score = _sleep_score(durationMinutes, quality) # score = 0-100 based on WHO guidelines
5
Store: Hash + Score Only
Database stores proof hash + computed score. Raw duration/steps/macros are NEVER written to DB.
health_sleep INSERT { user_id, date, sleep_score: 78.4, -- computed zk_proof_hash: sha256(proof) -- hash only -- NO durationMinutes stored! -- NO quality stored! }
6
Ring Score Updated
Sleep ring on HomeCanvas updates. V-Score event pushed. Streak tracked.
GET /v1/health/summary → { sleep: 78.4, activity: 62.0, nutrition: 55.0 } POST /v1/vscore/.../event { type: "health.sleep", delta: +3.2 }
Privacy Guarantees
Raw biometrics: device-only, never transmitted
Server stores: score + proof hash only
30-day history: aggregate only, no raw values
3 Biometric Types
Sleep: duration + quality → sleep_score
Activity: steps bucketed ("8000–8999")
Nutrition: macro ratio → nutrition_score
FLOW 08 · Prediction Markets
Prediction Market
Binary prediction markets on-chain. Anyone creates a market. Users bet $VIVA on outcome A or B. Oracle resolves at deadline. 2% platform + 1% creator fee. Winners claim proportional payout.
1
Create Market
Creator defines question, two outcomes, and resolution deadline.
POST /v1/predictions/markets { title: "BTC > $100k by Dec 2026?", outcomeA: "Yes", outcomeB: "No", resolveAt: "2026-12-31T00:00:00Z" } → PredictionMarket.createMarket()
2
Users Discover & Bet
Market listed in Predictions tab. Users bet $VIVA on A or B. $VIVA locked in contract.
POST /v1/predictions/markets/{id}/bet { outcome: "a", amount: 50.0 } → PredictionMarket.bet(mktId, A, 50e18) → $VIVA locked: poolA += 50 VIVA → bets[mktId][user][A] += 50
3
Market Closes
At resolveAt, no new bets accepted. Oracle watches for deadline.
require(block.timestamp >= m.resolveAt) // market.status = Status.Pending
4
VIVA Oracle Resolves
Off-chain oracle (Chainlink / VIVA validator) calls resolve with winning outcome.
PredictionMarket.resolve(mktId, Outcome.A) // or: cancelMarket(mktId) → full refunds market.status = Status.Resolved market.winner = Outcome.A
5
Winners Claim
Winners claim proportional share of loser pool minus fees.
POST /v1/predictions/markets/{id}/claim → PredictionMarket.claimWinnings() totalPool = poolA + poolB = 10000 VIVA platformFee = 10000 * 200 / 10000 = 200 creatorFee = 10000 * 100 / 10000 = 100 winnerPool = 9700 VIVA // My 50 VIVA bet out of 6000 poolA: payout = 50/6000 * 9700 = 80.8 VIVA
+30.8 VIVA profit on 50 VIVA bet
Fee Structure
Platform: 2% (PLATFORM_FEE_BPS=200)
Creator: 1% (CREATOR_FEE_BPS=100)
Winners: 97% of total pool
Cancel = Full Refund
Oracle can call cancelMarket()
All bets refunded 100%
No fees on cancellation
FLOW 09 · Live Audio
Audio Room
LiveKit-powered WebRTC audio rooms. Hosts set stake gates and V-Score requirements. Host earns $VIVA per listener-minute. Listeners can raise hand to become speakers.
1
Host Creates Room
Host sets title, optional stake gate (lock X VIVA to join), V-Score gate, and privacy.
POST /v1/rooms { title: "Web3 Alpha Talk", stakeGate: 10, // 10 VIVA to join vscoreGate: 200, // Rising+ required isPrivate: false } → LiveKit.createRoom(roomId) → rooms INSERT
2
Listener Joins
Listener taps Join. System checks V-Score gate and stake gate. If stake required → $VIVA locked.
POST /v1/rooms/{id}/join // Checks: if vscore < room.vscore_gate → 403 if stakeGate > 0: stakes INSERT { user_id, amount: 10, purpose: "room", lock_until: room.end } VIVAToken.transferFrom(user, contract, 10e18)
3
Get LiveKit Token
Backend issues signed LiveKit JWT. Token encodes room, user, and role (listener by default).
GET /v1/rooms/{id}/token → livekit.AccessToken{ apiKey, apiSecret, identity: userId, grants: { roomJoin: true, canPublish: false } // listener }.toJwt()
4
WebRTC Connect
React Native LiveKit SDK connects to SFU server. Audio streaming begins. Low-latency (<200ms).
// screens/Rooms/RoomScreen.tsx import { useRoom } from '@livekit/react-native-sdk' room.connect(livekitUrl, token) room.on('participantConnected', ...) room.on('trackPublished', ...)
5
Listener Raises Hand
Listener requests speaker slot. Host sees request in panel.
POST /v1/rooms/{id}/raise-hand // room_participants UPDATE: raised_hand=true // push notification to host
6
Host Promotes to Speaker
Host promotes listener. LiveKit grants publish permission. User can now speak.
POST /v1/rooms/{id}/speakers/{userId}/promote → livekit.RemoteParticipant.setPermissions( { canPublish: true }) room_participants UPDATE: role='speaker'
7
Host Earns Per Listener-Minute
Earnings calculated: listeners × minutes × rate. Credited from room stake pool + protocol mint.
// Cron: every 60s while room active listeners = room_participants.count earn_per_min = listeners * 0.01 VIVA VIVAToken.mint(hostId, earn_per_min, ROOM) earn_events INSERT { source: "room_host", amount: earn_per_min }
+0.01 VIVA / listener / minute
8
Room Ends
Host ends room. Stakes returned. Recording (if opted-in) saved to IPFS. Summary pushed.
DELETE /v1/rooms/{id} → stakes refunded to all participants → if recording: IPFS.pin(recording) → room_participants: all left → summary push notification
